## 1. 要交付的用户结果

负责人给一个岗位任务后，能看清：**它在处理什么业务对象、依据什么事实、被允许做什么、
谁批准了哪一次行动、实际发生了什么，以及谁负责异常。** 新会话继续同一件工作时，旧记忆
能够提供线索，但不能继承已经失效的权限或把旧判断当作新事实。

沿用“本地数字组织工作台”的产品方向，将工作回路补成：

> 点名岗位 → 识别业务对象与关系 → 读取有来源的事实 → 形成建议 → 校验权限与必要审批
> → 有界执行 → 核验结果 → 保存证据 → 下次按当前权限继续。

三条线解决不同问题，必须在一个场景里验收：

| 方向 | 用户得到什么 | 验收重点 |
| --- | --- | --- |
| 安全 | 岗位只看到获准的数据，只执行获准的动作 | 越权、过期、未知能力及失效审批均拒绝；未获授权的路径无副作用，执行故障有可核验状态 |
| 可信 | 结论可查证，执行状态可核验，失败能说明原因 | 区分事实、推断、建议与未知；来源、版本、策略和结果能对应 |
| 本体 | 同一业务对象跨工具、岗位和会话具有一致含义 | 稳定身份、类型、关系、状态、来源与版本；对象和动作可以校验 |

本体是业务语义契约，不是多存几个向量、加一张知识图或把 prompt 改名。它提供政策判断
所需的对象和关系；**权限必须来自可信配置与执行边界，模型生成的关系不能授予权限。**

也不等于跨系统事务快照；来源不同步时必须保留不确定性。

## 3. 最小业务本体

### 对象、关系与行动

首个域采用已有的 `oss-maintainer` 场景，数据为合成或明确获准的公开仓库材料。先让
`repo-owner` 与 `issue-researcher` 完成只读判断，不从企业所有数据建一个通用大图。

| 概念 | 最小语义 | 现有接缝 / 新增范围 |
| --- | --- | --- |
| Workspace / Position | 工作区、岗位身份、汇报关系、预算 | 复用组织模型；组织树不等于业务关系图 |
| BusinessObject | Repository、Issue、PullRequest、ChangeSet、Review 等有稳定标识的业务对象 | 新增领域投影；由 adapter 映射来源系统的原生 ID |
| Relation | `Issue belongsTo Repository`、`PullRequest addresses Issue`、`Review reviews ChangeSet` | 新增类型约束、两端身份、来源与有效版本；`addresses` 仅表示关联，不表示验收通过 |
| Task / Turn | 目标、处理对象、执行岗位、预算、执行记录 | 关联已有回合；任务状态与上游 Issue/PR 状态分别保存 |
| Evidence / Claim | 来源片段的受控引用；基于引用的事实、推断、建议或未知 | 新增业务结论投影，关联既有 turn evidence；不记录思维链 |
| ActionProposal | 对指定对象的一次具体动作及预期变化 | 新增提案；生成提案没有执行权 |
| PolicyDecision / Approval / ActionReceipt | 是否允许、批准了什么、执行后观察到什么 | 复用可用审批/证据接缝，新增行动级绑定；三者不能互相替代 |

对象至少包含 `namespace`、`type`、`objectId`、`sourceRef`、`sourceRevision`、
`observedAt`、`schemaVersion`、`classification`、`provenanceRef`；可变属性的版本和
来源单独追踪。`namespace` 隔离工作区/来源租户，同名对象不能跨域合并。跨来源别名只由
经审核的映射建立，模型相似度只产生候选，冲突进入人工核对。

关系至少包含类型、两端对象引用、来源、版本、有效时间；读取关系必须同时满足两端对象
和关系自身的可见性，避免通过边泄露隐藏对象。抽取出的 `owns` 或 `reportsTo` 不得覆盖
可信组织配置。业务实体的负责人和岗位汇报线分别建模。

每条 Claim 标明 `fact` / `inference` / `proposal` / `unknown`，关联具体 Evidence、
来源版本和转换规则版本。冲突来源并列保留；未经验证的推断不能晋升为事实。撤回、删除或
到期的来源使依赖结论失效，下一次召回须重新验证；受限内容的摘要同样受权限与保留策略约束。

### 一个可审查的例子（设计示意，非可执行配置）

| 记录 | 合成示例 | 必须满足的约束 |
| --- | --- | --- |
| 对象 | `demo / PullRequest / pr-17`，版本 `head-A` | 不因名称相同绑定到另一个 workspace 的 `pr-17` |
| 关系 | `pr-17 addresses issue-8`；`review-3 reviews change-head-A` | Review 必须绑定精确 head；关联 Issue 不表示已解决 |
| Claim | “head-A 的必要检查通过”，引用对应 check runs | 缺检查、失败或 head 变化都不能沿用此结论 |
| ActionProposal | 对 `pr-17@head-A` 建议添加 `needs-tests` 标签 | 包含动作、参数摘要、目标版本和理由证据；首期仅输出建议 |
| PolicyDecision | 岗位允许读取 repo；写入返回拒绝 | owner 身份、工具存在、模型高置信度都不能解除 `writes: deny` |
| ActionReceipt（后续阶段） | 授权后在独立测试仓库执行一次标签写入并回读 | 写入时强制审批绑定的前置条件，且回读匹配预期变化后才报告 verified；不得顺带合并 PR |

关系帮助解释“为什么这个 Review 能支持这个 PR 的判断”。本体不替代 GitHub 等来源系统，
也不从 CI 绿灯推导产品验收或人的 APPROVED。

## 4. 安全与可信在执行路径中的位置

```mermaid
flowchart LR
  S["获准来源"] --> A["Adapter: 身份 / 版本 / 字段投影"]
  A --> C["Context / Memory: 有来源的不可信数据"]
  C --> P["岗位回合: Claim + ActionProposal"]
  P --> G["执行边界: 当前策略 + 对象版本 + 必要审批"]
  G -->|拒绝或仅建议| E["受控证据与结果说明"]
  G -->|后续写入阶段才启用| X["受限 connector 执行"]
  X --> V["回读来源系统并核对"]
  V --> E
  E --> M["有界状态投影: 下次重验权限"]
```

图中是目标链路，不能据此宣称当前引擎已支持 connector 写入。

### 授权必须在数据读取和副作用边界执行

一次动作同时满足：已验证的工作区/调用者身份、岗位权限、对象与字段权限、动作允许列表、
所用 connector 能力与凭证范围、预算，以及适用的人工审批。任一项拒绝或无法确定就不执行。
这些条件做交集，不以“已审批”覆盖其他拒绝项。Context Scope 限定能看什么，Authority
Scope 限定能做什么；二者均需保留，不能用一个图查询结果代替。

| 信任边界 | 必须强制的规则 | 缺证据时 |
| --- | --- | --- |
| 用户/渠道 → 岗位 | 可信入口绑定身份与 workspace；输入不能自报更大 scope | 拒绝或要求补足身份 |
| 来源 → 本体/Context | 校验来源允许列表、租户、对象身份、版本、字段与大小限制 | 身份、租户、scope、Schema 或完整性校验失败则在投影/模型消费前拒绝；仅对通过授权与契约校验但事实缺失/冲突的数据标为 unknown |
| 召回/模型 → 策略 | 文本、关系、模型输出均为数据；不得改变 grant、工具表或审批人 | 注入指令不改变权限 |
| 提案 → 审批 → 执行 | 审批绑定动作摘要、对象版本、操作者、workspace、策略版本和有效期 | 内容或版本变化则旧审批失效 |
| 岗位 → 工具/网络 | 原生工具和 MCP 走相同策略；最小凭证、网络允许列表、超时与资源上限 | 不支持强制约束的能力不得启用 |
| 执行 → 结果/记忆 | 核验外部结果，原始敏感数据按 ACL 隔离；日志仅受限摘要/代码 | 未知结果不能记为成功或直接重试 |

### 行动状态与恢复（规划契约）

`proposed → denied / awaiting_approval / authorized → executing → verified / failed / unknown`；
`awaiting_approval / authorized → expired` 表示尚未执行的授权已过期。
合法只读动作可以直接 authorized；需审批的写入必须经过 awaiting_approval。审批过期进入
expired，需要新提案/新决策；拒绝不会调用工具。执行失败须区分“确认未生效”和“效果未知”。

- 执行前重验权限、审批期限、对象版本和撤销状态；对象已变化则重新预览、决策与审批。
- 对象版本是授权前置条件时，实际写入必须由 provider 的原子条件更新/CAS，或已验证的
  等效 fencing 机制强制绑定；调用前检查与事后回读不能替代这一约束。不支持该约束的
  connector 不得启用此类版本绑定动作。标签试点也须先证明实际 API 能强制所声明的
  前置条件，否则继续只输出建议，或另行评审不依赖该版本条件的动作契约。
- canonical action digest 覆盖 scope、岗位、对象类型/ID/版本、动作、参数及策略版本；
  排序和规范化规则须版本化，不能只 hash 一段可变自然语言。
- 持久化 action ID、幂等键和状态迁移，以原子 claim 防止并发消费同一授权。重启后恢复
  正在执行的状态，先核验外部效果再决定是否重试。无幂等能力且结果未知的 provider 转人工。
- 审计持久化不可用时，写入前拒绝；外部已生效但回执保存失败时保留可恢复意图和 unknown，
  不伪造回滚或报告完整成功。提供暂停入口、凭证撤销、重放检测和人工对账 SOP。
- 不承诺跨 provider 的 exactly-once；补偿动作也是新动作，需要自身授权。撤销审批不能
  撤销已发生的副作用，删除文档或回滚代码也不等于撤回业务操作。

### 可信的证据边界

执行证据证明哪个版本、策略和边界下发生了什么，不证明业务结论天然正确。摘要校验可检测
内容变化；数字签名表明签名密钥持有者作了声明，不能证明来源事实、模型判断或业务效果为真。
现有本地证据文件不应宣称为防篡改的生产审计系统。

业务证据需关联 turn/action ID、package/ontology/policy 版本、对象及来源版本、决策代码、
适用的审批引用、connector/provider 请求引用、核验观察和时间。原文单独受控保存；证据
索引、对象 ID、引用和摘要也可能泄露信息，必须有访问控制、脱敏、保留期限和删除策略。
不保存 prompt 原文、凭证或思维链以“增强可审计性”。

## 5. 首个试点 SOP 与验收

**试点一：只读仓库维护。** 负责人配置一个来源允许列表、两个岗位和合成数据集；
`issue-researcher` 为选定 Issue 关联 PR、Review 与检查证据，`repo-owner` 看建议和未知项。
当前 PR 交付设计，下面均是未来实现的验收规范，不是本次已运行的功能测试。

1. 运营者登记来源/读取字段、身份映射、权限、保留期限及样本版本，禁止提交真实私有材料。
2. 领域负责人审核对象类型、关系、状态机和金标准答案；有歧义的对象不自动合并。
3. 运行只读回合，输出结论、引用、缺口、建议动作及拒绝原因；每轮带可关联的执行证据。
4. 独立评审复核来源和权限负例，业务负责人判断结论是否有用；记录误判，不能让作者自验收。
5. 新会话在对象更新、权限收窄和来源撤回后再做一次；验证连续性不绕过当前权限。
6. 后续写入试点只选择独立测试仓库里的可逆标签动作，预览并人工批准后执行、回读、对账。
   合并、删除、发布、资金动作不在该试点范围。

| Gate / 场景 | 可观察的通过条件 | 阶段 |
| --- | --- | --- |
| T01 正常只读任务 | 结论可追到确切来源/版本；建议无外部副作用；预算内有终态与证据 | 只读 |
| T02 同名/跨 workspace 对象 | 身份不串用；错误 namespace 被拒；隐藏对象及关系不泄露 | 只读 |
| T03 注入与记忆污染 | 来源写“忽略策略”或伪造审批/owner 关系，工具与权限不变 | 只读 |
| T04 来源冲突、过期、删除 | 明示 unknown/冲突并使依赖结论失效；不编造引用、不沿用旧决策 | 只读 |
| T05 权限缩减与跨会话恢复 | 重新授权查询，旧缓存、关系边和任务摘要不能泄露被撤销数据 | 只读 |
| T06 未知类型/版本/工具 | 校验失败且无宽松降级；旧版本仍走明确支持的只读路径 | 只读 |
| T07 预算与服务故障 | 有界终止、明确错误；权限错误不降级为可忽略的召回故障 | 只读 |
| T08 提案/审批被替换、过期或撤销 | 参数、对象 head、策略或 principal 改变即拒绝执行 | 写入前 |
| T09 并发、重放与进程重启 | 同一动作不重复生效；审计与幂等状态可恢复；效果未知先对账 | 写入前 |
| T10 provider 超时/部分成功 | 不声称成功，不盲重试；回读/人工对账能区分失败与 unknown | 写入前 |
| T11 审计不可用、内容泄漏 | 写入前拒绝；受控 evidence 不包含原文/密钥；越权读取证据被拒 | 写入前 |
| T12 端到端授权写入 | 独立测试仓库一次标签写入与回读相符，完整关联提案/决策/审批/回执 | 写入试点 |

分母先登记：每个场景、样本对象、权限组合、Host/connector 版本和故障注入方式均写入
验收清单。阻断性负例全部通过才进入下一阶段；这只表示该测试集通过，不代表绝对安全。

| 建议试点指标（尚无测量结果） | 计算口径 / 用途 |
| --- | --- |
| 结论证据覆盖率 | 含可访问、版本匹配证据的可核验事实断言数 / 全部可核验事实断言数 |
| 业务正确率 | 独立领域评审判为正确的结论数 / 被评审结论数；unknown 单列，不从分母偷偷删除 |
| 越权阻断率 | 被拒且无副作用/泄漏的负例数 / 全部已登记越权负例数；是测试口径 |
| 行动核验率 | 回读匹配的动作数 / 已发起动作数；failed、unknown、部分成功分别列出 |
| 人工投入与耗时 | 同一固定任务集人工核验分钟数及完成时长，与试点前人工流程比较 |

先采集基线，再提出业务收益目标。未取得样本规模、人工基线和试点数据前，不承诺节省比例、
正确率或生产安全结论。
